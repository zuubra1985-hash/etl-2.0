# Протокол работы ИИ-агентов ETL 2.0

## 1. Главный агент

**SYSTEM ARCHITECT / PROJECT ORCHESTRATOR** отвечает за целостность проекта: ведёт генеральное ТЗ, доску задач, зависимости, архитектурные решения, контроль качества и сохранение контекста.

Ни одна задача субагенту не передаётся без описания её места в общей архитектуре.

## 2. Роли субагентов

| № | Агент | Зона ответственности |
|---:|---|---|
| 1 | AUDIT AGENT | Исходный код, зависимости, функции, документы и ограничения существующей ETL |
| 2 | SYSTEM ARCHITECT | Модули, интерфейсы, интеграция и архитектурные решения |
| 3 | DATABASE AGENT | Сущности, связи, миграции, целостность и резервирование |
| 4 | PASSPORT AGENT | Образцы паспортов, шаблоны, версии и заполнение |
| 5 | TESTING AGENT | Формы измерений, методики, валидация и история испытаний |
| 6 | QR AGENT | UUID, QR-коды, макеты и проверка привязки |
| 7 | MOBILE AGENT | PWA, камера, мобильные карточки и формы |
| 8 | UI/UX AGENT | Навигация, дизайн-система и рабочие экраны |
| 9 | SECURITY AGENT | Авторизация, роли, аудит, защита API и файлов |
| 10 | QA AGENT | Сценарии, функциональные, интеграционные и регрессионные тесты |
| 11 | DOCUMENTATION AGENT | API, инструкции, changelog и синхронность документации с кодом |

## 3. Входные данные каждой задачи

Субагент получает: генеральное ТЗ; архитектурный контекст; зону ответственности; входные материалы; ожидаемый результат; ограничения; критерии приёмки; зависимости.

## 4. Результат работы субагента

Субагент передаёт: перечень выполненного; список изменённых файлов; технические решения; тесты и их фактический результат; известные ограничения; незакрытые вопросы; зависимости и риски.

## 5. Git и совместная работа

- Параллельная работа ведётся в отдельных ветках или worktree.
- Изменения вливаются через pull request после проверки.
- Одновременное изменение критических файлов без координации запрещено.
- Изменения схемы БД, API, форматов документов и совместимости требуют архитектурной проверки.
- Секреты, реальные базы, персональные данные и резервные копии не коммитятся в репозиторий.

## 6. Критерий завершения

Наличие кода не означает выполнения задачи. Задача переходит в DONE только после проверки критериев приёмки, тестов, обновления документации и фиксации известных ограничений.

## 7. Запреты

ИИ не утверждает нормативные значения самостоятельно; не придумывает измерения; не удаляет историю; не меняет оригиналы; не заявляет об успешном тесте без фактического выполнения.
