# ETL 2.0 — предварительный план тестирования

План уточняется после аудита исходной программы, утверждения архитектуры и получения образцов документов.

## 1. Регрессионные тесты существующей ETL

- Запуск приложения в поддерживаемой среде.
- Проверка каждого ранее существовавшего сценария.
- Формирование контрольных протоколов на исходных данных.
- Сравнение структуры, таблиц, нумерации и реквизитов с эталонными документами.
- Проверка импорта и экспорта.
- Проверка обновления/установки без потери пользовательских данных.

## 2. Тесты данных

- Уникальность ID оборудования и испытаний.
- Связь измерения с испытанием и объектом.
- Сохранение версии методики и прибора в испытании.
- Сохранение фактического измеренного значения без автоматической подмены.
- Повторное испытание создаёт новую запись.
- Исправление сохраняет первоначальное значение, новое значение, автора, дату и причину.
- Проверка транзакционной целостности.

## 3. Документы

- Формирование протокола из сохранённых измерений.
- Соответствие утверждённому шаблону.
- Повторная генерация не уничтожает ранее утверждённую версию.
- Оригинал паспорта не изменяется.
- Новая запись паспорта связана с испытанием и протоколом.
- Корректное версионирование и экспорт/печать.

## 4. QR и мобильный интерфейс

- QR однозначно открывает карточку нужного объекта.
- QR не раскрывает конфиденциальные данные и не заменяет авторизацию.
- Корректная работа камеры и сканирования.
- Мобильная форма не допускает случайного повторного сохранения.
- Понятная обработка потери сети и ошибок API.

## 5. Безопасность и восстановление

- Проверка ролей и запретов на действия.
- Проверка журнала критических операций.
- Проверка резервной копии базы и файлов.
- Тестовое восстановление в отдельной среде.
- Проверка отсутствия секретов и пользовательских данных в репозитории.

## 6. Сквозной интеграционный сценарий

Создать объект электродвигателя → загрузить паспорт → присвоить UUID → сформировать QR → открыть карточку со смартфона → выбрать испытание → ввести измерения → сохранить → проверить историю → сформировать протокол → обновить раздел паспорта → создать новую версию → проверить отсутствие дублирования.

## 7. Правило отчётности

Для каждого теста фиксировать идентификатор, среду, входные данные, шаги, ожидаемый результат, фактический результат, статус и ссылку на дефект. Не заявлять об успешном тестировании без фактического запуска.
